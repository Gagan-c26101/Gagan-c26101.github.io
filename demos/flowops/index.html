Current implementation

This is the path a real event takes in the current portfolio demo. The browser stores workspace tasks locally; when a webhook is configured, selected events are sent to your Google Apps Script endpoint.

01 · EXPERIENCE

Content brief, task board, approval status and activity log.

Working

02 · EVENT DELIVERY

Webhook bridge

Sends task and content events as JSON to the configured Apps Script /exec URL.

Configure URL

HTTPS POST · browser fire-and-forget

03 · DESTINATION

Google Sheets

Apps Script validates/parses the payload and appends an audit row to FlowOps Events.

Requires setup

Apps Script · Google Sheets

Task / content event→HTTPS POST→Apps Script→Sheet row
Delivery is not acknowledged to the browser because the demo uses no-cors mode. Verify the event in the Google Sheet. Slack notifications are optional and only work after a Slack Incoming Webhook URL is stored in Apps Script Script Properties.

Reliability & security decisions

  • Never put Slack/API secrets in the public frontend.
  • Use server-side authentication and request validation before production.
  • Add durable queue, retries and idempotency for reliable delivery.
  • Track delivery acknowledgements instead of assuming a POST succeeded.
  • Keep human approval before publishing external content.
